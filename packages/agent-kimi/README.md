# Kimi Code integration

Shared Desktop/CLI integration for MIT-licensed `@moonshot-ai/kimi-code@2.1.1`, pinned in the manifest and pnpm lockfile. Harness requires Node.js 24+; upstream requires 22.19+. Workspace and deployed packages include the runtime. `KIMI_EXECUTABLE` may select a compatible JS entry or executable; startup rejects a version mismatch.

`code-session.cjs` launches upstream `kimi web` with a private `KIMI_CODE_HOME`, random token and authenticated REST/WebSocket. Configured MCP failures block prompting. A dead process, stream gap or missing initialized history fails visibly without replaying tasks. Upstream owns its agent loop, tools, skills, compaction and persistence; no SDK or upstream source is copied or forked.

Model API format is independent of the agent kernel. Official MiniMax `/v1` profiles resolve to generic Chat Completions even if an old profile selected Kimi API. Kimi keeps its existing thinking policy; compatible APIs use the native model default rather than imposing `high` on every vendor. Vendor toggles, effort tiers and token budgets are not universally interchangeable; see [API compatibility and OpenCode findings](../../doc/model-api-compatibility.md) for tested behavior and remaining gaps.

Real Harness sessions retain macOS Seatbelt or Linux x86-64 bubblewrap/seccomp. Native Bash, Write and child MCP processes can write session/scratch storage while the engineering project and protected runtime remain read-only. Linux requires enabled user/PID namespaces; unavailable boundaries fail without fallback. The [Windows candidate](../../doc/windows-agent-isolation.md) requires native Microsoft MXC BaseContainer/PSEC, local NTFS and the system .NET Framework compiler. It uses the pinned standalone executor, checks required capabilities and refuses ACL-based or unprotected fallback. Native and packaged Windows qualification remains pending; older Windows without the required native capabilities cannot start protected tasks. Registered external MCP runs through the host Runtime with Scope, arguments, snapshot and approval checks, and saved unverified evidence. Independent application-control plugins remain unavailable. See [security](../../SECURITY.md) and [industrial Runtime](../../doc/p0-industrial-runtime.md).

Host metadata and Runtime tools use `tool-server.cjs`, an authenticated local MCP service. Zod validation and handler-time Broker checks remain mandatory. `industrial_action_call` enters the persistent host Runtime with Scope, expected State identity and approval, returning canonical artifacts and verification separately from Agent completion. Its mutually exclusive `inputs`/`inputsJson` transport preserves nested engineering types without coercion; JSON is limited to 256 KiB. `industrial_tool_describe` supplies scoped input guidance, and current DomainState artifact references remain bounded to 2 KiB.

Only this internal `harness_adapter` MCP entry sets `toolTimeoutMs` to 3,660,000 ms: the generic workspace contract permits a one-hour task, with a minute reserved for result delivery and cleanup. This finite communication watchdog prevents Kimi's default 60-second MCP timeout from cutting off an otherwise permitted Runtime action. It does not extend industrial execution deadlines, external-service timeouts or startup limits, and does not guarantee arbitrarily long approval waits. Explicit Stop still cancels the owning Runtime; close also waits for cleanup. The fixed Kimi client does not enable progress-based timeout renewal; no synthetic progress or upstream patch is used. The real Kimi heartbeat regression runs a protected 65-second workspace task within its declared 75-second execution budget and checks the persisted result without replay; Runtime timeout/cancellation tests separately verify process cleanup.

Project root instructions and skills remain mapped into a stable writable session workspace. Native `.kimi-code/skills` and `.kimi-code/AGENTS.md` take precedence; when absent, legacy `.kimi` inputs map to those paths. `.agents/skills` uses native discovery; `.skill/`, `.skills/`, Claude/Codex roots and selected Broker/plugin skill batches enter `extra_skill_dirs`. Parsing, progressive disclosure and duplicate priority remain upstream-owned. The real Project joins the native workspace through `add-dir` with `persist: false`, including after restart; project configuration is not rewritten. Roots update when a native process starts, not while its skill catalog is running. Project skills grant no industrial tool permission. Remaining cwd/ancestor/command limitations: [native compatibility audit](../../doc/kimi-native-compatibility-audit.md).

Harness tool output is bounded to 16 KiB UTF-8 JSON, Industrial Context to 8 KiB. Capability details and checkpoint observations are paged. These boundaries do not replace native compaction or imply engineering acceptance. Capability-gated image inputs reach native providers; media payloads and known credentials are redacted from events and snapshots.

`KimiSession` preserves the UI/CLI event interface. Harness identity maps to a native `session_*` in `harness-native-session.json`; compatibility covers kernel version, Scope, model, MCP configuration, plugins and approval mode. Old messages and diagnostics remain readable, while continuing an old Python chat starts a new native context segment. Missing initialized history fails instead of silently creating an empty context.

Diagnostics retain original `kimi-code.event` frames and mapped `sdk.event` rows. Messages-API snapshots are saved conversation, not full model context or HTTP requests, and do not reconstruct per-step context. Path/size/hash validation and bounded readers remain. Historical context/wire files use the read-only legacy parser.

Approval policy is handled by Harness while native manual mode retains interactive questions. Single/multiple choices, custom text and dismissal use the native question API. Noninteractive CLI preserves a question and returns `needs_input` with exit code 2. Stop requests native cancellation, then closes only the target session after its bounded timeout. Late events, repeated Stop, failures and cleanup retain existing session isolation.

Desktop/CLI supply `resolveSession` and `sessionInitialized` persistence callbacks. Core's resource manager reserves active/resident capacity before native prompting; idle eviction closes the process without removing persistent storage. Temporary homes are cleaned on close, persistent homes on explicit chat deletion. See [resource guards](../../doc/session-resource-guards.md).

Tests exercise the pinned real runtime against controlled local providers: approvals, Scope revocation, authentication, images, project guidance/search, identity recovery, cancellation, parallel isolation and native auto-compaction. Summary quality is trusted upstream; compaction tests check wrapper event/context/restore compatibility. Desktop release smoke runs the bundled archive through the macOS or Windows sandbox launcher. Evidence and platform limits: [migration record](../../doc/kimi-code-migration.md).


Native `subagent.*` lifecycle events become display states and summaries. Session-wide subscription retains child task/control events while the adapter filters child answer streams out of parent answers. Native step identity scopes delta offsets, so offset resets after a tool cannot discard the final answer. Background controls and Kimi-initiated follow-up turns stay observable after the user turn ends, holding resource leases until the native session is idle. Stop closes owned background work and settles pending controls. Harness does not schedule follow-up prompts, rewrite subagent profiles, or recreate orchestration. The actual native desktop test covers foreground/background approvals, native follow-up tool/question controls, Markdown and saved history; [release acceptance](../../doc/release-readiness-20261007.md).

Native `task.started`/`task.terminated` and their legacy aliases track background Bash and child-owned tasks once. Terminal tasks retain leases until `task.notified` delivers their result or a successful native `WaitFor` delivers completion itself. Native work-state events and automatic follow-up turns keep the session busy through the notification gap. Background logs stay open through continuation. Headless awaits `waitForBackgroundIdle()` before its final result, including cancellation cleanup; background questions retain `needs_input`/exit 2, and the explicit run timeout covers background work. Scope/Runtime approvals remain in their existing handlers. See [background compatibility](../../doc/kimi-background-compatibility.md).

Stream byte offsets are scoped to native step identity; durable frame sequence/epoch deduplication still rejects replay and gaps. Child approvals and question requests retain their owning agent even with a different child turn ID. Real coder-child approve/reject/cancel is tested; question forwarding has a frame-boundary test because the pinned coder profile does not expose AskUserQuestion. Runtime requests are snapshotted before approval; previews include actual bounded details. MCP connections and active cancellation are owned by the calling chat.

Application metadata tools `list_results` and `select_result` use this existing authenticated bridge, independently of industrial Runtime availability. Selection accepts registered IDs and the current revision only; it changes display emphasis, without an extra model turn or engineering Action. Runtime tool results also return the host-bound groups, so producer declarations reach the Agent as well as TaskService events. [Task results](../../doc/task-results.md).
