# 大版图 Viewer 方案与阶段记录

状态：**首阶段流式显示已实现，完整外存/实例复用方案仍待实现**。2026-10-19 用户授权实施。当前构建、单元及本机后端 301 次请求验收通过（192 次 tile XY 对照、64 次接缝检查零差异/假墙），Chrome 实际预览与新版原生 Electron 待完成；未取得超大版图容量或持续性能资格。本页不承诺图形规模、吞吐或 FPS，支持边界以 [Viewer 当前实现](viewer-layer.md#版图-25d-示意层叠)为准。

本机后端证据见 [原始报告](evidence/layout-streaming-20261019/tile-stress-report.json)与[固定输入清单](evidence/layout-streaming-20261019/fixtures.json)。这些是有界局部查询和概览的后端结果，不是浏览器 GPU 或原生 Electron 验收。

已落地：私有内容绑定快照、逐层真实概览、相机驱动局部精确 tile、明确精度状态/拾取、受限缓存/队列与过期响应处理。输入 128 MiB、快照每进程 256 MiB；前端缓存 CPU 128 MiB/GPU 64 MiB/250000 三角形，后端缓存 64 MiB/队列 32；768 MiB RSS 是软监控；外部采样不可用时可用受支持平台的 worker 自报峰值和边界检查，不是硬隔离。recorded result 仍保留共享 TaskService 的来源、配套及哈希成本。

精度增量：tile 局部浮动原点、DBU 网格约束 LOD（最深 30 级）及相机世界焦点保持已实现，纯前端回归 25/25 通过。实际 HTTP Host 的 32 层 metadata→cancel→overview→detail 链路通过（首层 detail 66 个三角形）；该证据不包含 GPU 或原生界面。

尚未落地：磁盘索引/外存解析、cell/array 的 GPU 网格实例复用、跨进程资源统一配额和完整规模资格。近千万逻辑图形 fixture 仅按层概览/局部查询，不表示其三角形全量驻留。以下保留实施前的瓶颈基线和完整目标，用于区分当前增量与后续工作。

目标是在软件层面把“全局看得见、局部看得准”作为一个连续查看过程：全局使用明确标注的概览，放大后按需加载原始 XY 几何。不得为绕过预算自动改变用户的 ROI、静默删除细线或隐藏图层。GDS/OAS 图层继续按 layer/datatype 独立选择，包括未知用途图层；没有 PDK 映射就不解释金属、通孔、物理高度或制造顺序。

## 实施前基线（历史，不代表本次流式路径）

| 环节 | 当前行为 | 对大版图的影响 |
| --- | --- | --- |

| 几何 | [`geometry.py`](../packages/viewer-builtin/src/layout/geometry.py) 对整个请求 ROI 的可见层做递归实例遍历、变换、裁剪和三角化 | 重复实例在结果中成为独立三角形；跨可见层累计限制 5000 次递归图形出现（非去重图形）、100000 个源顶点、单图形 10000 点、80000 个三角形、256 层。单图形点数在裁剪前检查；8 秒检查只在 Python 循环边界执行，不能中断内部 C++ 裁剪/合并/分解。超限拒绝整次请求 |
| 调度和传输 | [`raster.cjs`](../packages/viewer-builtin/src/layout/raster.cjs) 串行执行请求，通过单行 JSON 返回全部三角形；几何 worker 硬超时 15 秒 | 没有 tile 流、请求级取消或有界任务队列；前端忽略旧响应不等于停止计算。超时会终止二维/几何共用的 worker 并丢失数据库；load 超时为 120 秒，没有 RSS 硬配额。JSON 与临时对象均占内存 |
| GPU | [`layout-scene.ts`](../packages/viewer-builtin/src/layout/layout-scene.ts) 在 `setGeometry()` 中删除旧 buffer，转换全部顶点/法线，再上传新 buffer；CPU 保留顶点用于拾取 | 整个 ROI 全量替换，没有 GPU tile 复用与常驻预算；峰值不能只按最终三角形数量估算 |
| 视域 | [`LayoutViewport.tsx`](../packages/viewer-builtin/src/layout/LayoutViewport.tsx) 在进入立体时从二维捕获 ROI，立体内 zoom 仅更新 GPU 相机 | 在立体中继续放大不会重新提取更细数据；后续需由 ROI 和活动相机共同决定 tile 可见性 |
| 源身份 | [`main.cjs`](../apps/desktop/electron/main.cjs) 的 `checked()` 每次流式读取整文件计算 SHA-256；[`layout-request.cjs`](../apps/desktop/electron/layout-request.cjs) 在请求前后分别校验 | 每次二维/几何请求会重复扫描源文件。直接把当前请求拆成大量 tile 会把这个代价成倍放大；不能删除哈希或仅用 stat 冒充等价校验 |

现有 Sobel 局部几何审计见 [原始报告](evidence/layout25d-geometry-20261019/sobel-geometry-audit.json)：四个 ROI 按层核对顶面 XY 并集与源 Region，差异为零。15 µm 区域逐层审计的图形总和超过当前单次组合预算；它不是超大场景并发渲染或整图容量证据。

## 目标行为与后续完整方案

- 打开后先展示可追溯的全局概览和实际加载状态；概览与精确几何有明确标识。概览可以是分层栅格/覆盖度表示，不能把缺少细节显示成“没有几何”。
- 平移、缩放和图层选择保持用户指定的范围。优先补齐当前区域的可见层，再逐步细化；尚未完成的 tile/层显示加载中、失败或概览状态，不以完整就绪冒充部分结果。
- 精确几何只在可承受的工作集内加载。需要精确拾取时，只对就绪的精确数据确认；在概览上点击可触发局部加载，不能把概览像素当成精确器件或网络。
- 用户可单独显隐、选择或隔离每一图层。2D、XY 俯视和示意层叠使用共同的源版本、cell、XY 导航范围和图层集合，各自视角可保留；requested ROI 与活动相机共同决定加载哪些 tile，不暗中缩小 ROI。Z 高度继续只是展示参数。
- 保留共享缩放/Fit、滚轮/捏合、全屏和相机状态。资源不足时保留已有可用视图并说明受限的区域/层；不自动放大、缩小 ROI 或丢弃用户选择。

## 分层数据管线（部分已实现，见页首）

保持 Registry 选择与既有只读 Viewer 入口。导入、索引、几何转换归 Built-in Viewer 的受控显示服务；Desktop 负责项目/Artifact 身份、会话和窄 IPC；通用 Core 不增加具体 GDS 或 PDK 规则。派生索引不是新的工程事实，不产生 Verification。

### 1. 导入与只读源快照

先建立受控、只读、按内容寻址的源版本，再运行索引/渲染。一次流式复制和哈希同时绑定源 Artifact 摘要，并检测复制期间变化；快照不匹配、项目切换或源版本失效时拒绝复用。快照保存位置、权限、空间预留、清理和崩溃恢复由宿主管理，不接受 renderer 任意路径。

后续 tile 请求核对会话绑定和快照身份，不重新读取原始大文件两遍。源文件修改后使当前源版本失效并要求重新打开；不能把旧快照与新源混合。文件监听、stat 可用于发现变化和加速失效，但不是内容一致性的完整证明。若需要比当前更高效的内容绑定机制，须先用并发写入、同大小改写及快照篡改测试证明边界，不能仅去掉现有检查。

快照会增加磁盘读写和存储需求，应在导入前预留空间，失败或取消后回收。导入的文件大小、目录边界、格式、top cell 选择和解析器身份均需明确，不能把“扩展名可识别”当成成功导入。

### 2. 保留层级与空间索引

对 cell 的局部几何建立可复用网格/轮廓及包围盒索引，实例仅保留变换和引用。规则 array 保留行列数、步长及变换，查询时只生成与视域有关的实例范围；不预先把全库实例或整个 array 展平。镜像、旋转、缩放和嵌套变换必须保持源 XY 结果。

在顶层范围建立确定性的空间 tile 索引，tile 内按 layer/datatype 分开。索引引用 cell/实例与跨 tile 图形，避免在每个 tile 重复保存完整源对象。查询首先剔除不可见的 cell/实例，再对目标层和 tile 做有限提取；重复单元可共享 GPU 网格并使用实例绘制。实例数量、查询展开数量也有预算，不能让“未展开的 array 描述很小”掩盖实际绘制规模。

这些路径需要验证固定解析器能提供哪些索引/随机访问能力；若不能，须增加有界预处理或外存索引，不能假设已有 `load_layout()` 自动具备磁盘分页。

### 3. 概览与按屏幕误差选择 LOD

LOD 由当前投影、像素尺寸及允许的屏幕误差选择，不能仅按文件大小或固定图形数猜测。全局可使用按层的覆盖度/栅格概览，中间级别按需细化，局部切换精确轮廓；精确级别不做几何简化。极细线、窄缝和孔洞在概览中的表达必须可解释，不能把抽样结果宣称为精确拓扑。

明确每一级 LOD 的误差定义、边界重叠方式、选择阈值与上下行滞回，避免缩放边界反复切换。保持旧的同源覆盖直到新的 tile 就绪，再按 tile 替换，减少闪烁和整屏空白；一个请求失败不会清空其他已完成层。实现前先选择最小可验证方案，不同时引入多个未经基准比较的渲染后端。

### 4. 逐步加载、取消与反压

请求包含会话 epoch、源版本、cell、tile、层、LOD 和优先级。优先级建议为当前可见精确需求/拾取、当前视域概览缺口、细化、有限邻域预取；相同任务合并，过期视域任务撤销或降级，禁止无界预取。

取消必须覆盖排队、解析/裁剪、编码、传输和 GPU 上传。协作式检查不能中断的原生操作由受控 worker 超时/终止兜底，清理后不能让旧响应发布到新会话。根据内存与队列预算限制并发和单次上传大小，消费端未释放额度时生产端暂停；不是仅增加更多 worker。二进制分块传输和可转移 buffer 是候选方案，仍须测量 IPC 拷贝与实际生命周期。

## 总资源预算与缓存身份

预算同时约束单任务、单 Viewer 和整个应用，包括隐藏标签页；具体数值由目标硬件的基线测量决定，当前不承诺容量。

| 资源 | 需要计入的工作集 | 超额策略 |
| --- | --- | --- |
| CPU 内存 | 导入数据库/索引、裁剪和三角化临时对象、响应编码、解码、拾取数据、正在上传的缓冲区 | 准入前预留；先撤销预取、逐出可重建数据，再降低并发或明确拒绝。临时峰值也须受限 |
| GPU | 已驻留 tile/实例/索引 buffer、纹理概览、选择 pass 和待替换 buffer | 按字节计账与 LRU；保留必要可见覆盖，释放后才补充，不因隐藏标签继续无限常驻 |
| 磁盘 | 源快照、cell/tile 索引、LOD 缓存、临时导入文件 | 全局配额、LRU 和原子提交；磁盘不足/缓存损坏可恢复，不能影响源文件 |
| 队列/传输 | 等待任务数、估计/实际字节、在途块、单帧上传工作、后台预取 | 有界队列、去重、过期取消和反压；可见需求也不能绕过总预算 |

缓存键至少绑定源 SHA-256、parser 及转换器版本、数据 schema、dbu、cell 身份、层 key、tile 坐标/边界策略、LOD/误差参数与几何生成参数。层叠高度、颜色等纯显示状态若在 shader 中应用，不必污染源几何缓存；若已烘焙进几何则必须入键。索引/缓存读取需校验内容和长度，禁止跨项目错绑或接收未验证的外部缓存。

采用分层 LRU：cell 共享几何、CPU tile、GPU tile 和磁盘派生数据分别计账、引用计数及淘汰。当前可见项的保留也有上限；不足时退回明确标注的同源概览，而非无限增加“不可淘汰”集合。记录预算占用、命中率和逐出原因供诊断，不把诊断数字当成工程结论。

## 几何正确性与困难输入

- **Tile 边界不能生成假墙。** 内部切片边只用于覆盖分区，不能像真实外轮廓一样挤出侧壁。当前提取会把裁剪后轮廓全部挤出，包含 ROI 切边；不能直接逐 tile 复用。顶底面可裁剪，侧壁应来自真实源边界与 tile 的交集，内部切边不封口；需标记边来源、规定唯一覆盖归属及必要 halo，验证接缝、重复边和闪烁。总体 ROI 截面若显示，须单独标注。
- **保持真实 XY。** 精确模式保留孔洞、path 宽度/端点规则、层级变换与 dbu。独立 Region/轮廓比对须覆盖 tile 拼接后并集；不能只比较三角形数量或截图相似度。
- **大坐标精度。** 源坐标/索引保留足够整数精度，避免未经检查地转换成 JavaScript Number。GPU 采用共享世界坐标基准下的 tile/cell 局部原点及明确变换，上传较小的局部值；禁止按各自 tile box 独立归一化后直接拼接；验证极大坐标上的细间距、负坐标和连续平移，不能用 Float32 全局坐标悄悄吞掉细线。
- **单个巨大多边形。** 一个对象可能包含极多顶点/孔洞，单 shape 计数或普通 tile 查询都不能保证便宜；当前 10000 点上限发生在裁剪前，缩小 ROI 或直接 tiling 不能解除；必须限制输入和中间复杂度，研究有界分解或外存预处理。禁止先完整三角化再声称“分 tile 限流”。无法在预算内处理时明确拒绝该输入/精确层级。
- **展平且几何几乎不重复的文件。** 实例复用收益可能接近零，仍依赖磁盘索引、逐 tile 精确数据和概览；不能用重复标准单元测试结果替代这类输入。
- **高重叠和大量图层。** 几何可缓存并不代表像素填充、透明叠加和拾取便宜；分别测量并限制绘制工作，不擅自合并或隐藏未知图层。

## 超大输入的导入边界

前端 LOD 无法解决解析阶段 OOM。若完整加载超出目标硬件预算，必须选择经过验证的受限导入进程加磁盘索引/外存读取路径，或者明确报告当前输入不支持。导入需有内存/时间/临时磁盘配额、可取消、worker 崩溃隔离和清理；当前 Python 子进程加超时不等于已具备完整 OS 资源隔离。

预检不能只依据压缩文件大小；层级展开规模、顶点/孔洞、阵列、压缩比和索引开销都影响成本。能在预算内取得的元数据用于准入，无法提前确定时在受控进程中边处理边计量，失败保留原文件与可诊断原因。远端解析只是未来可评估选项；没有用户明确授权，不上传源文件或派生内容，也不把远端容量作为本地缺口的默认兜底。

## 测试矩阵与阶段 Gate

| 维度 | 必测输入/场景 | 通过证据 |
| --- | --- | --- |
| 数据形态 | GDS/OAS、深层 cell、旋转/镜像/缩放、巨大规则 array、展平独特几何、单巨大多边形/多孔、跨 tile 图形、密集多层 | 固定源摘要与可复现生成参数；精确区域和独立源 oracle 的差异检查 |
| 尺度/精度 | 全图→局部→全图、极大/负坐标和细间距、不同 dbu、空区域、边界线/孔洞 | XY 误差与拓扑检查、tile 拼接无裂缝/假墙；概览误差单独报告 |
| 调度/资源 | 快速缩放平移、频繁显隐、连续选择、多标签/隐藏视图、冷/热缓存 | 峰值 RSS/GPU/磁盘/队列字节、在途任务数、取消后回收；有界且无陈旧帧污染 |
| 故障/身份 | 导入/三角化超时、worker/GPU 丢失、OOM、磁盘不足/损坏缓存、源并发改写、项目切换、快照篡改 | 明确状态、取消/重开可恢复、无跨源混用、源字节不变、没有静默缺层 |
| 原生交互 | 文件树→Registry→概览→局部精确、图层独立选择、2D/XY 对比、拾取、wheel/pinch/Fit/全屏/Esc | 对每个实际目标 OS/GPU 独立验收，不由开发机器结果外推安装包资格 |

1. **G0：测量与契约。** 保留当前失败保护，记录导入/哈希/提取/JSON/上传各阶段耗时和峰值。选定真实获授权大文件与合成困难输入、目标机器、预算和验收阈值；明确支持范围。没有基线不承诺“亿级”“秒开”或固定 FPS。
2. **G1：源快照与导入准入。** 证明内容绑定、变更失效、磁盘配额、取消/崩溃回收；判断当前解析路径是否能满足首批目标。不能满足时先落实外存导入或明确不支持，再做前端扩展。
3. **G2：精确 tile 与层级复用。** 先建立固定小数据的 exact oracle、实例/array 查询、按层 tile 缓存和二进制分块；通过孔洞、变换、精度、接缝和无假墙检查，再接 UI。
4. **G3：全局概览、LOD 与有界调度。** 验证误差标识、连续导航、优先级、真正取消、反压和 CPU/GPU/磁盘总预算；全图不能因预算不足空白或伪装成完整精确视图。
