# 本机 Agent 使用当前用户权限

2026-10-20，[PD-088](product-decisions.md#pd-088三平台本机-agent-统一使用当前用户权限) 将 macOS、Linux、Windows 的本机 Kimi 启动统一为当前用户权限。这取代此前 macOS Seatbelt、Linux bubblewrap/seccomp 的 Agent 启动硬依赖，以及 PD-086 只对 Windows 放开的平台例外。没有可选 strict Agent 模式，也不通过宿主提权或修改 ACL 取得权限。

## 实际权限

Kimi 原生 Bash、文件工具和后代进程拥有当前用户已有的权限，可以读写该用户可访问的工程、配置和其他文件。会话工作目录、输入副本、项目绑定和审批不构成操作系统隔离；不能宣称工程、Runtime 源码或本地证据对这些进程只读。宿主服务凭据仍从 Agent 环境及诊断中过滤，但这不限制读取当前用户可读的凭据文件，也不提供网络隔离。

共享启动器保留明确的可执行文件、参数和环境，固定 Kimi home 与会话目录，保留持久上下文、临时 scratch、项目指令和技能映射。会话目录与工程目录分开，避免将聊天文件当作工程输入。诊断明确报告 `mechanism: current-user`、`osIsolation: false`、`projectWritable: true`；模型上下文如实说明当前用户权限。执行配置参与原生上下文兼容键，旧隔离模式的聊天历史保留，续聊使用兼容的新上下文段。

关闭仍先请求原生 shutdown，取消和退出清理本次拥有的进程与 scratch，保留持久聊天。普通进程清理不承诺 OS 容器或 Job Object 对宿主崩溃后全部后代的强制回收。

## 保留的 Runtime 边界

- 通过共享 Runtime 调用的工业工具仍检查项目、领域、当前状态、工具范围、输入快照及审批。显式远端准备和工具授权继续绑定精确文件、目的地、身份与任务；普通聊天启动不要求先上传。
- 共享工作区编辑仍检查内容 hash、路径、链接及托管证据目录。原生文件操作不经过该入口，因此这些校验不是所有本机写入的强制拦截层。
- 已声明的本地任务继续使用 `packages/domain-runtime/src/task-process.cjs` 的独立隔离。只读快照、专属输出目录、禁网和宿主 socket 限制保持；Linux 执行这种任务仍需 bubblewrap 与可用命名空间。缺少条件只拒绝相应任务，不阻止 Agent 启动。
- Docker 任务的固定镜像与资源限制、远端服务的认证和租户/项目隔离、快照校验、工具授权、配额与沙箱释放保持。移除本机 Agent 包装器不改变远端 worker 的边界。

## 验收与历史

平台资格仍以原有 OS/CPU、原生内核、安装包及领域 Profile 的实际结果为准。移除启动依赖不自动支持 Intel Mac、未验证 Linux 架构或其他专业软件。当前用户启动、环境过滤、普通工程写入、审批、取消/恢复和打包消费须按目标平台验证；声明式任务隔离与远端服务完整链路分别验证。

历史文档与 evidence 中的 Seatbelt/bubblewrap 写入拒绝是当时版本的实测事实，保留原结果；它们不再描述当前 Agent 模式，也不代替新模式的验收。[Windows 说明](windows-agent-isolation.md)保留平台特有的启动与取消细节。
