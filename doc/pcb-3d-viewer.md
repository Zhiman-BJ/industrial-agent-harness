# PCB 三维 Viewer

PCB 文件仍通过项目文件树 → Artifact SHA-256 → Registry → 本地 KiCanvas iframe 打开。板图工具栏提供 2D/3D 模式；原理图继续使用二维。三维板图复用同一个固定版本 KiCanvas 的 parser、BoardPainter 和已变换绘图原语，元件模型引用同样来自该 parser；不另写 KiCad 文件解释器、不启动工业程序；本地查看不需联网。用户明确请求官方模型时，由宿主进行按需下载，iframe 自身不连接外网。

## 查看与身份

- 拖动旋转、右键平移、滚轮/捏合缩放；工作区的缩放、Fit 和全屏复用现有导航。
- 选择图层名可单独查看该层，复选框控制可见层；滑条展开叠层。展开只改变显示位置，不修改设计坐标或工程叠层。
- 三维铜层/焊盘点选保留源 UUID、所属封装和网络；元件实体可点选回真实源封装。顶面与底面组件沿用源坐标、封装旋转及模型变换，在二维中查看复用源封装选择/网络高亮。
- 元件实体有独立显隐控制，随所在板面展开；隐藏或展开只改变显示，不改模型或封装源数据。
- 已闭合板框来自真实 Edge.Cuts，源文件提供厚度和完整叠层时沿用其数值。缺少层厚时明确显示“层间距为示意”。未闭合/不支持的几何与预算限制必须提示，不使用包围盒编造板框。
- 二维/三维切换、标签页和全屏保留视角、图层及选择；关闭 iframe 取消构建并释放 GPU 资源。图形上下文丢失时返回二维并显示错误。

## 显示范围

当前显示真实板图的铜层、焊盘、过孔相关几何和丝印。本轮加入项目内真实 **STEP（`.step` / `.stp`）与受支持的静态 KiCad legacy VRML（`.wrl`）元件实体**；STEP 保留模型颜色，模型放置沿用源封装与模型记录的变换，不按焊盘包围盒猜测器件外形。缺失、不支持、失败与超预算的模型分别报告，不以方块或其他占位实体替代。此前“元件实体一律不加载”的初版范围已由本轮接入更正。

VRML 目前只接静态三角面且不允许外部依赖。非单位顶层变换及暂未支持的复杂 `center` 语义会明确拒绝，不声称覆盖通用 VRML 场景、脚本、外部纹理或 Inline 模型。模型拒绝或缺失时仍可查看真实焊盘与源封装身份。

显示能力继承固定 KiCanvas 的范围。二维与三维一致不等于与原生 KiCad 所有格式特性完全等价：特殊倒角/自定义 padstack、内层通孔焊盘环、复杂盲埋孔、阻焊实体和相交/跨板缘孔需要对应支持或明确限制。制造文件的简化 Gerber/Excellon 预览不作为这个三维场景的数据来源。

这只是只读几何预览，不生成 DRC/ERC、碰撞、装配或制造通过结论，也不更新 DomainState、源文件或已有验证结果。

## 模型文件与离线打包

本地模型必须位于当前项目真实目录内，优先按下表解析。官方模型缓存仅能通过下节所述宿主逐项授权，不开放任意项目外目录。

| 源模型引用                                                          | 解析位置                                                            |
| ------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `models/component.step`                                             | 板文件所在目录下的相对路径，仍须在项目内                            |
| `${KIPRJMOD}/libs/component.wrl`                                    | 当前项目根目录下的 `libs/component.wrl`                             |
| `${KICAD6_3DMODEL_DIR}/Resistor_SMD.3dshapes/R_1206_3216Metric.wrl` | 项目根目录下 `3dmodels/Resistor_SMD.3dshapes/R_1206_3216Metric.wrl` |
| 其他 `${KICADn_3DMODEL_DIR}` 或 `${KISYS3DMOD}`                     | 同样以项目根目录的 `3dmodels/` 为基准                               |

`3dmodels/` 映射是本 Viewer 的离线项目打包约定，不表示读取本机 KiCad 的全局库或继承这些环境变量的任意外部目录。用户准备模型时需保留其来源和许可证；Viewer 不自动查找外部安装库，打开文件不自动联网下载。绝对路径、未知变量、越出允许基准目录的路径及符号链接真实目标越界均拒绝。资源由受限通道提供，并与源文件及模型 SHA-256 快照绑定；模型变化必须重新打开，不继续沿用旧几何。

## 官方 STEP 按需下载

本轮接口接入增加“下载缺失模型”显式操作：本地项目模型优先，其次复用与当前声明匹配的已验证缓存。普通打开、切换 2D/3D、缺失模型检查与下载计划均不发起模型网络请求。只有用户点击后，宿主才按当前板文件快照和官方目录确定所需条目，交共享依赖管理器的通用 `dataLibraries` 获取；这与原生应用安装、容器准备是独立资源路径。

官方目录由外部 PCB Pack owner 维护，固定为 KiCad `10.0.7`、commit `8d4070daa0fa3f7a7f3c176f4ca7bffc4df392be`，清点为 **7,252 个 STEP、105 个 family 目录**。每个条目保留准确路径、原始文件 SHA-256、字节数、来源 revision 和许可/署名信息。Harness 消费固定发布声明，模型下载与缓存由共享管理器执行，不在 Renderer 硬编码镜像或让项目指定任意 URL。目录全量清点不等于全量下载或全部模型已验收；整库预下载不在本轮实现范围。

宿主只把匹配当前项目/源哈希的精确 `sourceRef`、资源根、路径、大小和摘要映射交给模型解析器。`KiCadRuntimeManager` 的可注入 provider 在打开时仅 `resolve` / `plan`；显式准备才 `ensure`，并重新核对会话与源快照。关闭、切项目、失效 token 或源已变化时不得把迟到下载附到另一个视图，也不得接受 Renderer 扩大的文件根或目录授权。

下载受预算与取消控制，完成大小和 SHA-256 验证后才可复用；中断、损坏或不匹配缓存不能当成可用模型。离线且缓存完整时可继续显示，缺失时如实提示；下载只写共享资源缓存，不更改板文件或模型引用。官方数据准备完成仍须通过原有模型解析、时间、内存和 GPU 预算。

**不自动进行 WRL → STEP 替换。** 官方 `10.0.7` 目录的上述 7,252 项均为 STEP；源板引用旧 `.wrl` 而本地缺文件时，不能靠同名 STEP 猜测外形或变换。用户已有的本地 legacy WRL 保持原支持范围。自定义或目录内无法精确匹配的引用继续明确不可用。

## 资源与边界

源文件保留 16 MiB 单文件、64 MiB 总量、32 文件、128 层表达式深度及项目路径/哈希校验；token 上限为 1,250,000，以容纳官方 5.8 MB 四层 video 板的约 107 万 token。三维捕获和 GPU 输出另设独立几何预算，分批构建并支持取消。达到预算必须报告省略和预览完整性；必要时继续使用二维。

捕获上限为 100,000 个原语、1,000,000 个点、30,000 个板框点及 20,000 个钻孔。渲染总预算为 1,200,000 个三角形，包含基板、铜层、钻孔遮罩和全部已接纳元件实例；单个多边形最多 65,536 点、单条折线最多 32,000 点。基板含孔总点数最多 32,000、钻孔最多 3,000，拓扑检查累计最多 8,000,000 次操作。钻孔遮罩最多 300,000 点。所有三角化先估算预算再分配，超限时明确省略对应几何；钻孔遮罩无法完整构建时省略整铜层，避免部分开孔伪装成完整板图。单个多边形的 Earcut 仍是受上述点数上限约束的同步计算，实际停顿需由 GPU 自测的 heartbeat 结果判断。

保留的 KiCad 标签各自拥有会话 token；A→B→A 可继续准备模型，关闭一个标签只释放它自身。最多保留 16 个会话、源与模型快照合计 256 MiB；超限时明确拒绝新打开，保留已有视图，不通过静默清除旧标签腾出额度。切项目或退出时释放全部会话。

模型资源另外限制为 8 MiB 单文件、64 MiB 唯一内容总量及最多 64 份唯一内容；最多收集 256 种源引用。重复内容按哈希共享快照。模型解析使用单线程 worker，单模型 10 秒、整批 60 秒时限，关闭 Viewer 时取消并清理。STEP WASM 的运行适配限制线性内存为 256 MiB；这不承诺 JavaScript 总堆、整个 renderer 进程或 GPU 显存也低于该值。

GPU 元件按共享几何的 `InstancedMesh` 渲染，保留 STEP 材质颜色，并以实例身份映射回源封装。共享几何节省重复存储，但三角形预算按每个实例累计；不能因复用一次几何就忽略重复组件的绘制开销。模型无法完整纳入预算时如实报告省略。

固定 KiCanvas 不保留的介质子层、重复层厚、异常铜层顺序会降为示意层距并提示。未支持的焊盘或省略几何会持续保留不完整提示；后续缩放、语言切换不会把该状态清除。

Three.js 与控制器作为固定本地资产随包分发，iframe 只通过现有白名单资源通道加载。使用 `script-src 'self' 'wasm-unsafe-eval'`、`worker-src 'self'` 与 `connect-src 'self'`（只为固定 STEP WASM 放行 WASM 编译，不允许 JavaScript `unsafe-eval`），不开放任意模型 URL、远程纹理、用户脚本、Node 或原生文件 API。

## 方案来源

调研了华秋 ECAD Viewer、tscircuit 3D Viewer 与 ECAD Forge。华秋的 KiCad 导出 GLB 路线可用于真实装配，但直接导入通用 GLB 不足以提供可靠的内铜层与源对象联动；tscircuit 需要额外的 CircuitJSON 转换，ECAD Forge 具有不同的许可证要求。本次沿用已固定的 KiCanvas painter 和 MIT Three.js，保持现有二维与文件边界。

对应版本及重建说明见 [KiCad Viewer](kicad-viewer.md) 和本地 vendor NOTICE/manifest；模型解析器及 STEP WASM 同样作为本地固定资产分发，保留各自许可。

## 验收

`pnpm --filter @industrial-agent-harness/desktop build` 后运行：

```sh
INDUSTRIAL_PCB3D_FIXTURE=/absolute/path/to/video.kicad_pcb \
  pnpm --filter @industrial-agent-harness/desktop test:kicad
```

真实多层板来源与摘要记录在 [fixture 说明](evidence/pcb3d-20261020/fixtures.md)。验收必须覆盖真实渲染、源 ID 点选、图层与展开、共享导航、全屏和语言状态保留、离线资源、故障返回二维及源码不变。平台与性能结果以实际生成的报告为准；未运行的平台不视为已支持。

本轮代码与 CPU 对账结果见[验收进度](evidence/pcb3d-20261020/acceptance.md)。GPU 结果须另有本次套件完成标记、退出码、截图与性能数据。

### 元件实体与下载接入验收状态

本轮 STEP/WRL 实体与官方按需下载接入的本次 CPU、真实 GPU/桌面验收仍在推进；不能将既有板图几何的对账、截图或自测通过记录当作实体模型已通过。后续需记录模型来源/摘要、实际加载与不可用数、顶底面变换、源封装点选、颜色、显隐/展开、预算/时限与失败恢复的本次证据。

仓库 LED 示例本身没有 `(model ...)` 引用，因此接入加载器也不会凭空出现器件实体。官方 video 四层板有 189 个封装、175 处模型引用（27 个唯一文件，均为 WRL）；单独的板文件不包含全部模型。本地官方 WRL 配套的原始字节清单与许可另有记录，但当前视图实际成功加载情况仍需本次验收，不能按引用数宣称模型已显示；video 的 WRL 引用也不能充当官方 STEP 下载流程的通过证据。来源见 [fixture 说明](evidence/pcb3d-20261020/fixtures.md)。官方 STEP 下载需另用源中明确引用可匹配 STEP 的项目，按 [Viewer QA 矩阵](qa-runbook/viewers-results.md) 记录显式触发、下载/缓存摘要、取消、跨项目/源变更拒绝及模型实际渲染。
