# Kimi 原生后台任务的外壳兼容

> 2026-10-20 执行政策更新：本页保留当时实现与验收记录。文中本机 Agent 的 Seatbelt/bubblewrap、工程只读或平台拒绝启动要求已由 [PD-088](local-agent-execution.md) 取代，当前三平台 Agent 均使用当前用户权限；声明式 Runtime 任务及远端沙箱隔离保持。历史实测结果不改写，也不代替新模式的平台验收。

2026-10-08，沿用 main 的子代理接入，补齐原生后台 Bash 与 Headless 生命周期。固定上游仍为 `@moonshot-ai/kimi-code@2.1.1`；不修改内核、WaitFor、超时策略、通知、调度、压缩或原生持久化。

原缺口：外壳只统计后台子代理，后台 Bash 不持有活跃资源租约；Headless 在首轮结束后立即关闭原生会话。命令终止也早于原生读取输出和启动后续回答，不能把进程终止直接视为整次执行结束。

共享适配层按 session 接收事件，过滤子代理正文，保留子任务控制事件。`task.started`、`task.terminated` 与 legacy alias 去重；终止到 `task.notified` 送达结果之间继续忙碌。成功的原生 WaitFor 会直接交付结果并省略自动通知，适配层通过其原生完成结果确认交付，不再等待被省略的通知。状态在收到事件时生效，避免首轮队列尚未读完时原生续答已开始的竞争。后续工具审批和问题沿用原有接口，宿主 Scope、快照、Runtime 审批和工程验收不变。

Headless 等待后台任务与原生后续回答结束，最终结果出现在取消清理与审批/问题失效事件之后。没有输入通道的后台问题仍返回 `needs_input`/exit 2；用户指定的总时限覆盖后台工作并返回 `timeout`/exit 124。Stop 关闭当前聊天的原生工作，连接异常明确失败并释放租约，不重放动作。后台诊断日志持续记录至空闲。

验收使用真实固定内核和本地可控模型响应，验证外壳兼容而不评价模型能力：

- 快速与延迟后台 Bash，首轮结束后自动续答、继续调用 Bash、审批、提问与回答；资源闲置期限设为 30 ms，后台运行期间仍保留活跃租约。
- 非零退出码回传、通知去重、显式 Stop、真实事件连接关闭后的失败与释放；无宿主重放。后台提问期间 Stop 后，使问题和未完成工具状态失效，同一聊天恢复时不泄漏旧工具事件。
- TaskOutput 对运行任务返回快照；WaitFor 超时后继续等待，等待阶段没有额外模型请求，直接完成后正常释放。后台 coder 子任务中的 Bash/WaitFor 也保持可见，子任务正文不混入主回答；TaskStop 抑制自动通知后不会无限等待。
- 实际受保护 Headless 的后台提问与总时限；独立打包 CLI 在仓库外使用随包内核、只读工程边界，完成后台命令和原生后续工具调用后才输出最终结果。
- 实际 Electron 通过桌面入口执行后台 Shell、审批后续工具、回答后续问题，聊天历史保留事件；既有前台/后台子代理、停止和历史恢复验收保留。

原生集成加入 macOS arm64/Linux x64 的必跑 CI；独立包测试沿用两平台的生产隔离门禁。其他平台的受保护执行支持范围不扩大。本地通过情况与 PR CI 结果分别报告。

本地 macOS arm64：新增 12 项真实原生后台回归全部通过；独立打包 Headless 与实际 Electron 子任务/Shell 操作通过。已有心跳、原生问题、自动压缩/重启和异常隔离 8 项通过；portable 286 项中 285 通过、仅已声明的可选 KLayout Viewer 跳过。架构与格式检查、Desktop TypeScript/Vite 构建通过。Linux 执行结果由新增的必跑 CI 提供。

2026-10-08 补充实际工作负载验收：在受保护 Headless 内后台执行仓库格式检查、Desktop TypeScript 检查和 Vite 生产构建，不插入人工延迟。两次均转换 2,117 个模块，生成 `index.html` 与 17 个资源文件，产物约 9.2 MiB，工程目录仍只读、产物写入原生 session scratch。原生 WaitFor 实际等待 3,056 ms；自动通知路径在首轮回答后等待约 3,308 ms，由原生完成通知启动续答，并用 Read 读取超过内联阈值的构建日志、Bash 检查生成文件，随后才输出 Headless 最终结果。等待期间没有额外模型请求；完整模型请求序列分别为 4 次和 5 次。这里验证外壳、内核和真实构建链路，不声称检验远端模型自主规划能力或分钟级远程任务。

可在已安装开发依赖的源码工作区复现：

```sh
node scripts/verify-kimi-background-build.cjs
node scripts/verify-kimi-background-build.cjs wait
```

该诊断使用可控模型和实际受保护 CLI，保存事件、模型请求、原生输出与摘要到临时证据目录；默认测试自动通知，`wait` 测试原生 WaitFor。它需要完整 Desktop 开发依赖，并非独立发行包或 CI 原生后台回归的替代品。
