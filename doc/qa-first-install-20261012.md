## 未修复问题

1. **P1：大归档在本次冷下载中触发默认总时限。** 需要改善生产传输的完成率，
   再按默认配置重新验收；提高测试超时或预置缓存不能作为修复证据。
2. **P1：Godot 安装就绪后的首次工程验证失败。** `--import --quit` 退出码为 0，
   但日志报告无法读取用户字体，严格验证正确拒绝判为通过。日志同时包含系统 CA
   初始化错误，现有 Owner 已精确处理该离线诊断，不能把它单独当成失败原因。
   三组独立对照确认是生产 macOS 沙箱的用户字体只读访问缺口，非本次隔离
   HOME 独有：隔离 HOME 无沙箱导入成功，正常父 HOME 加生产沙箱仍失败，
   仅在诊断中声明用户字体目录只读后导入通过。对照没有改变 Verifier，也没有
   证明完整工程任务成功；正式修复应收敛字体访问边界，不能开放整个 HOME。
3. **P2：Docker 检查时机过晚。** CAD 已开始 FreeCAD 下载才会检查后续 Docker
   资产；缺少 Docker 的用户可能先下载大归档再失败。已实测 CAD 顺序，PCB 存在
   同类代码顺序但本轮未重复实测。
4. **P2：新用户前提说明的本地化不完整。** 中文界面夹杂英文领域说明与 Docker、
   PDK、远程服务前提；CUDA 的“下载 0 B”也应明确只指本地客户端资产。

5. **P2：桌面正常退出未完成。** 快捷键和应用菜单两次退出均关窗但未结束主进程；
   只终止本次测试 PID 后重启可恢复历史，不能据此判正常退出通过。需进一步定位
   退出阶段的资源回收，当前没有确定单一根因。
