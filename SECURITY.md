# Security reporting and supported execution boundary

Report a reproducible vulnerability privately through this repository's GitHub Security Advisory page (`Security` → `Report a vulnerability`) when private reporting is enabled. If that option is unavailable, contact the repository maintainer through an existing private channel. Do not put credentials, customer designs, or an exploitable private reproduction in a public issue. No private inbox address or response-time commitment is invented here.

Include the affected commit/release, operating system, relevant Pack/runtime identity, minimal reproduction, impact, and a redacted event log. Runtime logs can contain customer source, paths and tool output; review them before sharing. Scope bypasses, cross-project artifact access, unsigned Pack activation, malicious Viewer input and evidence corruption are security-relevant.

Under [PD-088](doc/product-decisions.md#pd-088三平台本机-agent-统一使用当前用户权限), local Kimi processes on macOS, Linux and Windows run with the current user's ordinary permissions. Harness does not apply Seatbelt, bubblewrap/seccomp, MXC or restricted tokens to the Agent process, and offers no optional strict Agent mode. It does not elevate privileges or change host ACLs. This supersedes the former macOS/Linux Agent write boundary and the Windows-only exception in PD-086; historical test reports retain their original scope.

Native Bash, file tools and descendant processes can read or modify files and access services available to that user, including engineering projects, Harness configuration and locally stored evidence. Session workspaces, bounded input copies, environment filtering and approval prompts are not an OS permission boundary. No secret-read, network or arbitrary-code isolation is claimed for local Agent execution. Host service credentials remain filtered from the Agent environment and diagnostics, but this does not prevent access to credential files readable by that account.

Industrial mutations submitted through `industrial_action_call` still enter the host Runtime. It checks the bound project/domain, current state, Broker tool allowlist and caller approval, then persists Action and engineering evidence. Registered external MCP services use approved host Runtime Actions with pinned schemas/surfaces and stored, redacted responses; these trusted services may affect resources outside project roots, and their results do not establish engineering acceptance. These controls apply to Runtime calls and do not intercept native file or shell operations.

| Path                                      | Boundary and qualification                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local Agent on macOS, Linux and Windows   | Current-user execution, with explicit launch arguments, filtered environment, persistent session storage and cancellation cleanup. This policy does not expand supported CPU architectures, operating-system versions, packaged application qualification or Domain Pack qualification.                                                                                                         |
| Intel Mac and unqualified architectures   | Existing installation and runtime qualification limits remain. Removing an Agent sandbox dependency does not establish support.                                                                                                                                                                                                                                                                 |
| Declared local Runtime tasks              | `packages/domain-runtime/src/task-process.cjs` retains separate Seatbelt or Linux bubblewrap/seccomp isolation: read-only input snapshots, a fresh writable output directory, no network or host sockets, bounded time/logs/output. Missing prerequisites still reject that task; they do not prevent local Agent startup. This is not a host secret-isolation guarantee or a CPU/memory quota. |
| Docker Runtime tasks                      | Immutable inspected image IDs, read-only inputs/root filesystem, network restrictions and CPU/memory/PID limits remain.                                                                                                                                                                                                                                                                         |
| Remote industrial service                 | Authentication, principal/project ownership, immutable snapshots, tool authorization, sandbox isolation, resource admission, artifact checks and confirmed release remain server-side requirements. The client does not substitute for the remote tenant boundary.                                                                                                                              |
| Trusted installed Pack code and testbench | Runtime executables remain trusted code. The application is not a general containment service for untrusted projects or arbitrary Pack code; use disposable environments for those workloads.                                                                                                                                                                                                   |

Approved workspace edits still check file hashes and reject runtime/evidence/dependency paths, symlinks and hard links. Only one project Runtime may own a durable store at a time. An interrupted Action is recovered as failed with insufficient evidence, never engineering acceptance. Acceptance establishes the declared verifier's bounded claim, not a production signoff. Local files are not protected against modification by other processes with the same user permissions.

See [local Agent execution](doc/local-agent-execution.md), [shared workspace](doc/shared-workspace.md) and [remote execution](doc/remote-execution.md). The [P0 implementation record](doc/p0-industrial-runtime.md) preserves the earlier exercised slice and its historical isolation results.
